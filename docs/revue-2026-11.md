# SlimDash 0.8.4 – revue du projet (13 novembre 2026)

Méthode : relecture du code, puis relevé automatique (position, taille, police, couleur de chaque
texte et icône) des cartes d'origine dans Home Assistant et des mêmes cartes dans SlimDash,
à 600 px de large. Vues comparées : `dashboard-slimdash` 0 et 2, `slimdash-demo` 0 à 4.
Classe Ancien relevée en détail ; Intermédiaire et Moderne relevées sur 3 vues.
Non vérifié : rendu réel sur la tablette (relevés faits dans un navigateur récent).

## 1. Légèreté : objectif tenu

- Page d'une vue : 16 Ko, 2,8 Ko compressée. CSS 5,1 Ko + JS 2,6 Ko compressés, en cache 24 h.
- JavaScript ES5 pur, une seule requête en attente, aucune bibliothèque.
- Une seule connexion à Home Assistant, rendu préparé côté serveur, par classe et à la demande.

## 2. Respect des limites par classe

| Classe | Constat | Gravité |
|---|---|---|
| Moderne | `gap` sur les rangées flexbox (`.hs`) : absent de Chrome 80–83 et Safari 13–14.0, pourtant classés Moderne. Les cartes d'une rangée se touchent. | bug |
| Ancien | Cartes demi-largeur en 49 % + 1 % : la colonne de droite s'arrête 6 px avant le bord des cartes pleine largeur (mesuré : 588 contre 594). | visible |
| Ancien / Inter. | La carte portail fait 134 px en Ancien et 164 px en Intermédiaire (148 dans HA). | visible |
| Moderne | Écart entre sections plus grand qu'ailleurs (titres décalés de 12 à 50 px en bas de page). | mineur |
| Toutes | Reste conforme : pas de flexbox ni de variables CSS en Ancien, SVG en sprite, `calc` préfixé. | ok |

## 4. Code

- `s.css` empile quatre générations de règles pour les mêmes éléments (pastille, jauge) ;
  `c-inter.css` en redéfinit une partie. Fonctionne, mais chaque retouche est risquée.
- `docs/rendus.md` décrit encore l'Ancien sans icônes ni graphiques.
- `Builder.rich` et `Builder.graphs` valent toujours vrai : les branches « texte seul » sont mortes.
- Aucun test automatique de non-régression du rendu.
